# 伙伴化桌宠：SOUL + 记忆 + 成长 结合规划（v1 讨论稿，2026-09-08）

> 背景：Cindy 交付了「伙伴」功能（PR #2829，400 文件/5.4 万行）——长期人格化 AI 角色。
> 代码不可移植（长在账号云+配额+三引擎协作+任务系统上，四样 LongMa 都没有且多为红线域）。
> 本文只做**理念级借鉴**：把桌宠从「状态指示小动物」进化为「有人设、记得住事、随使用成长的伙伴」。
> 定位：桌宠 M2（养成，已拍板放后面）的演进方向，与 M2 合并规划。

## 一、Cindy 伙伴的四条可借鉴理念

| 理念 | Cindy 的实现 | LongMa 可借的部分 |
| --- | --- | --- |
| 永久 Profile 与可换 Session 分离 | SOUL/记忆/技能在 Bot Home，物理会话每日 04:00 CAS 换卷归档 | **人格与会话分离**：人设是持久属性，聊天会话可换可弃 |
| 记忆持久 + 自动整理 | 记忆落 Bot Home，每日换卷即记忆整理 | 轻量记忆表 + 摘要整理（见下） |
| 能力沙箱（allowlist） | 伙伴不继承主程序的技能/MCP/项目上下文 | 伙伴会话独立装配：系统提示只含 SOUL，不注入项目上下文 |
| 极简创建 | 名字 + 自动头像 + 人设文本，不暴露工程概念 | 桌宠已有形象选择；加一段可编辑的人设文本即可 |

明确**不做**：多伙伴、伙伴间委派（collaborate_with_bot）、IM 式名册、账号云配额。

## 二、LongMa 适配形态（BYOK、无账号、单机）

### 分层模型

```
桌宠窗（人格前端：形象 = 成长阶段帧 + 状态机）
   │
SOUL 层（持久，userData/pet-profile.json）
   ├─ 人设文本（用户可编辑，如"你叫小龙，性格活泼，说话简短"）
   ├─ 成长阶段（蛋→幼年→少年→成年，M2 既有规划）
   └─ 记忆（userData SQLite pet_memories 表）
   │
会话层（可换）
   └─ 伙伴模式会话：系统提示 = SOUL 前缀；不注入项目上下文/技能清单
```

### 关键设计决策（v1 建议）

1. **记忆不重开 pi memory**：产品面已固定关闭 pi memory（§4.1，内核仍装配但未暴露）。
   伙伴记忆走**独立轻量表** `pet_memories(key, value, source, createdAt)`：
   - `source='taught'`：用户显式教的（"记住我喜欢简洁回答"）——伙伴会话中模型经专用工具写入
   - `source='digest'`：每日整理的会话摘要（关闭应用时或每日首次启动时，把最近的伙伴会话
     摘要成几条事实）——**不做后台自动跑模型**，摘要时机=用户关机/次日首次启动，用当前会话模型
   - 用户可见可删（设置→桌宠→记忆管理）；总条数上限（如 200 条，超出 LRU）
2. **伙伴模式会话**：桌宠点击/工具条「聊天」打开的会话自动带 SOUL 系统提示
   （复用现有 system-prompt 装配链，伙伴会话前缀注入人设+记忆要点 top-N）。
   主窗普通会话不受影响。会话是否为「伙伴模式」记在 sessions 表一列。
3. **成长 = M2 既有规划不变**：经验=使用量（活跃天数+当日 token 分位防刷），阶段驱动形象帧。
   成长绑定**全局**（一份经验三形象共享）仍是建议默认。
4. **SOUL 人设与形象解耦**：换形象（black-heels/qipao/dino）不换人设——人设属于伙伴本身。

## 四、待拍板决策点

1. 成长绑定全局还是主题（建议：全局共享，各主题出全套阶段素材，缺阶段临时回落缩放）
2. 伙伴记忆是否对所有会话可见（建议：仅伙伴模式会话，主会话保持干净）
3. 伙伴会话的工作目录（建议：独立 `userData/pet-workspace`，不碰用户项目）
4. M2 与 M2.5 是否合并为一个版本发（素材齐就合，素材慢就先发 SOUL——SOUL 零素材依赖）
